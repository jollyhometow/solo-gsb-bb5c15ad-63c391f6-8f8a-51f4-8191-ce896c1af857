# 会议议程实时重排

会议进行中，当某项议程实际结束时间晚于（或早于）计划时，**从当前时刻向后自动重排**全天议程的
Web 应用。FastAPI + SQLite + 原生 HTML/CSS/JavaScript，无前端构建步骤。

## 一键启动（Docker）

```bash
docker compose up --build
```

然后浏览器访问：

**http://localhost:8000**

停止：`docker compose down`（数据保存在命名卷 `agenda-data` 中，重启不丢）。

> 端口在 `docker-compose.yml` 的 `ports` 中配置，宿主机默认端口 **8000**，容器内端口 8000。

## 不用容器，本地直接运行

需要 Python 3.11+：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 http://localhost:8000 ，SQLite 数据库文件位于 `data/agenda.db`（首次启动自动创建并播种演示会议）。

## 功能说明

### 议程项属性

| 属性 | 说明 |
| --- | --- |
| 计划时长 | 原计划分钟数 |
| 最短时长 | 压缩时允许的下限，重排不会把议程压到比它更短 |
| 优先级 | 1–5，数字越小越重要、越先被保住；窗口不够时从 P5 → P1 依次压缩；同级时靠后的议程先压 |
| 不可压缩 | 勾选后该议程时长完全不动（等同于不参与压缩） |
| 固定开始（休息段） | 休息段锚定在固定时间，**任何重排都不移动** |

### 重排规则

1. 必须按议程顺序录入某项的**实际结束时间**，系统以该时刻为“当前进度”。
2. 已结束的块保持原计划时间不动；刚录入的议程块结束于实际时间。
3. 当前时刻之后，议程被固定休息段切成若干窗口：
   - 窗口放得下 → 按计划时长排列（前面省出的空闲会保留，不强行拉伸）；
   - 窗口放不下 → 按优先级从低到高压缩可压缩议程，但不低于各自最短时长；
   - 所有可压缩项都压到最短仍放不下 → 进入**冲突状态**，页面红色横幅 + 明细表列出：
     - 哪些议程项无法完整容纳（含各自超出分钟数）；
     - 总溢出分钟数；
     - 与哪个固定休息段重叠及其起止时间。
4. 固定休息段永不移动；若重排时休息段起点已被错过，会提示“该休息段已被错过，保持原时间”。
5. 顶部显示新预计结束时间与相对原计划的延误分钟数。

### 页面

- **双时间轴**：上行“原计划”，下行“新计划”，同一时间刻度左右对齐；颜色区分已结束 / 刚录入 /
  已压缩 / 冲突 / 固定休息，斜纹块表示冲突溢出，虚线为实际进度，红点线为新结束时间。
- **撤销**：`↩ 撤销最近一次录入` 会删除最新一条实况录入，时间轴回到上一状态（可连续撤销）。
- 议程项可上移 / 下移调整顺序、删除；可随时“新建会议”清空重来。
- 首次启动内置一份 9:00–11:45 的「产品迭代评审会」演示数据。

### 推荐试法

在演示数据上，给“需求优先级评审”录入一个晚于计划的实际结束时间（例如 10:40），
即可观察到：茶歇 10:30 固定不动 → 后续议程被压缩；若录入足够晚（例如 11:15），
则出现冲突明细与总溢出分钟数。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 获取完整状态（会议、议程项、录入、原计划/新计划时间轴、冲突列表） |
| POST | `/api/meeting/reset` | 新建/重置会议 `{title, start_time}` |
| POST | `/api/items` | 新增议程项或休息段 |
| POST | `/api/items/{id}/move?direction=up\|down` | 调整顺序 |
| DELETE | `/api/items/{id}` | 删除（级联删除相关录入） |
| POST | `/api/entries` | 录入实际结束时间 `{item_id, actual_end}` |
| POST | `/api/entries/undo` | 撤销最近一次录入 |

交互式文档：启动后访问 http://localhost:8000/docs 。

## 运行测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖核心重排算法：空闲吸收、按优先级压缩、最短时长下限、不可压缩保护、
固定休息段切窗、冲突与溢出分钟、连续录入与撤销后的视图。
